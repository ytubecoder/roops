# Roops — recurring automation harness (mechanical name: loops)

Custom thin harness for scheduled agent "loops" (recurring maintenance/monitoring jobs across ~/projects). **Status: BUILT + live-verified 2026-07-22** (real launchd firing, codex AND claude, findings memory/dispositions, enforcement denial, full dashboard matrix; 1028 hermetic tests via `bash tests/run-tests.sh` — 661 python + 367 shell, measured 2026-08-02).

**Fleet state (2026-08-23, cut over):** the fleet runs on the Debian guest **`firstparty`** as user `svc` under systemd user timers (`~/.config/systemd/user/loops-<name>.timer`, `loginctl enable-linger` on, `Persistent=true` — installs survive reboot; the old launchd-only reboot failure no longer applies). 12 loops armed there (five ads, gc-actions, hello-loop/-watchdog, kagi-ban, loop-sensei, tailnet-zones, phoneapp-cost-sync — the last is untracked, copied by hand with its credential) plus the console (`loops-console.service`, `loopctl console status`). **kagami is not installed anywhere** until its `gh` auth on the guest is decided. **llm is the data host only**: zero `com.loops.*` jobs, its checkout serves `bin/probe-server` + `probes/` to the guest over the forced-command ssh key, and its `.env` must never set `LOOPS_PROBE_HOST`. Ingress is interim: the tailnet URL still terminates on llm's dev-tailnet Caddy `@loops` route → `127.0.0.1:8929` → LaunchAgent `com.roops.console-bridge` (`~/Library/LaunchAgents`, persistent; `ssh -N -L` to the guest's loopback console) until the `loops` tailnet device is deleted and the guest's own Caddy vhost takes the name (runbook step 4). Deploy = push from llm, `git pull` on the guest (`probes/`/`bin/probe*` changes must land on BOTH before a loop that uses them is installed; `loopctl probe status` shows drift). State moves only via `loopctl snapshot`/`restore`. Everything else is supervised-only. Install state is machine-local: unit files/plists are never in git, so a fresh clone shows installed=False until reinstalled.

## Non-negotiables (from the plan — full rationale in docs/HARNESS_PLAN.md)
- Engine: **codex default** (`codex exec --output-last-message --output-schema`), claude switchable (`claude -p --json-schema`), local models later. Prompts engine-neutral; prefer CLI/curl over MCP.
- The real invariant (README "What Can Actually Change Things"): **deterministic code you wrote gets full power; the model gets a sandbox.** `precheck.sh` is trusted UNSANDBOXED bash (all network/file I/O belongs there); the **model** is contained by the four per-loop permission axes, never by prompt text alone. The whole current fleet sits at/near the report-only floor; widening an axis is a per-loop config change requiring written justification — never something inherited or assumed. Know which axis actually contains what: the **working-directory write sandbox**, `--tools`, and `perm_network=none` are the real containment. `exec_allowlist` is NOT — a non-allowlisted `echo` still ran under a one-entry allowlist (verified 2026-07-28), so treat the allowlist as intent, not as a boundary.
- macOS has **no `flock`, no GNU `timeout`** — use the fcntl lock helper + runner-owned process-group timeouts.
- Paperclip and hermes are OUT as harness (evaluated + rejected 2026-07; hermes cron is the documented fallback; `hermes` ≠ `hermes-local`). Never install `NousResearch/hermes-paperclip-adapter` v0.3.0 (frozen, buggy).
- All paths `$HOME`-relative (runs on macOS now, WSL later).

## Critical gotchas (cost real debugging time — the WHY matters)
- **A loop cannot declare its own displayed status when it emits findings.** Per `INTERFACES.md` §4.5, a NON-empty `findings` array makes `effective_status` = max severity of the unsuppressed findings and **discards the declared `status`**; only an EMPTY `findings` lets `status` through. A run that failed to write its action set declared `alert` and displayed **amber**, because its findings topped out at `warn`. If a run must surface red, it emits zero findings.
- **The engine's shell layer hard-denies any command containing both a brace and a quote** ("expansion obfuscation") — before the script runs, so the script cannot detect it. Any loop whose engine writes structured data needs a brace-free payload format. Full probe table + the allowed/denied pair: `docs/ENGINE_PROBES.md`. Do NOT let a model invent smuggling workarounds (`tr`, hex escapes, process substitution); the correct response to a denial is to remove the brace.
- **Model-emitted metrics get believed.** A run reported `inputs.missing: 4` while its own digest showed all four inputs healthy, tripping the dashboard's alert threshold on good data. Metrics a precheck can compute should be computed there and copied verbatim, never left to the model.
- **codex's Linux sandbox needs two things the bare binary does not ship:** `bubblewrap` (`apt`) on PATH and the `codex-code-mode-host` companion next to `codex` (0.149+). Without them a `perm_local_exec=allowlist` loop (the five ads loops) still shows `completed` — the engine just reports "Action set not written — execution host unavailable" and nothing else alarms. Found in the 2026-08-23 rehearsal; `codex sandbox --full-auto -- python3 -c 'print(1)'` is the one-line check (runbook prerequisite 7).
- **`loopctl` resolves its root from `LOOPS_ROOT`/`--root`, never from where the script lives.** On a host with two checkouts (the guest's prod clone + a rehearsal clone) `bin/loopctl restore` run from the rehearsal dir restored into the PROD clone. Always pass `--root` (or export `LOOPS_ROOT`) when more than one root exists.
- **A plist file in `launchd/` does not mean installed.** `loopctl` checks plist + `launchctl print`; the dashboard (§10 amendment 2026-07-30) checks file presence only, to stay subprocess-free and hermetic. Five ads-* plists existed with nothing bootstrapped (written 2026-07-28, never loaded — ads scheduling is explicitly phase 2 per B-03), making the garden show 巡/stale for loops that would never fire. Orphaned plists are dead files: verify with `launchctl print gui/$(id -u)/com.loops.<name>`, then delete them.
- **`loopctl`'s global flags use two deliberately different argparse flavors — do not "simplify" them into one.** `_common_parser(hidden=True)` builds the top-level parser's copy (real defaults, `help=SUPPRESS`); `_common_parser(suppress_defaults=True)` builds every subparser's copy (`default=argparse.SUPPRESS`, normal help). The reason is mechanical: argparse's `_SubParsersAction.__call__` parses a verb's trailing tokens into a **fresh** namespace and then copies every key of it onto the outer one — so if a subparser's `--root` carries a real default, `loopctl --root R status` resolves `R` correctly and then silently clobbers it back to `_default_root()`. That shipped once and meant `--root <sandbox> install <loop>` bootstrapped a launchd job in the **live** fleet at exit 0. `serve` additionally takes an `include_from=False` flavor (the console always reads `loops.d`), and `main()` rejects a pre-verb `--from` with `serve` because the top-level parser's `--from` is hidden and would otherwise swallow it. Pinned by `TestGlobalFlagPlacement` (both placements, every flag).
- **An imported loop's proposed precheck lines are emitted COMMENTED, and `[read-only?]` is an advisory hint — not a guarantee and not a boundary.** `precheck.sh` is trusted unsandboxed bash (see the invariant above), so the only real safety property is that the line is commented out; the classifier's label is a heuristic with known residual escapes (enumerated in `docs/SKILL_IMPORT.md` §6). Two adversarial rounds closed `git status && rm -rf`, `ls | xargs rm -rf`, `cat <payload>/etc/hosts` and `&`/`$( )` splitting; the enumeration keeps yielding, which is why the answer is "a human reads every line before uncommenting", not "tighten the regex once more".
- **Generated pages must fetch NOTHING on load** — dashboard and report pages alike (the reports screen was retired 2026-08-02). The rule is about *references the browser dereferences*, not the substring `http://`: no webfonts, no CDN scripts, no `<link rel=stylesheet>`, no `@import`/`url()` at a remote host, no `src=`/`srcset` off-box (including protocol-relative `//cdn/x.js`, which contains no `http://` at all). Inline everything; `data:` URIs are fine. **Navigation `<a href="https://…">` is fine** — following a link is user-initiated. So is a URL sitting in escaped report text, which real findings genuinely contain (a probe reporting `http://127.0.0.1:9/dead` refused a connection), and so is `xmlns="http://www.w3.org/2000/svg"`, which is an identifier, not an address. Enforced by `tests/html_selfcontained.py` (itself tested by `tests/test_html_selfcontained.py` — a scanner nobody tests passes everything vacuously). The older "no `http://` substring anywhere" phrasing was both too strict and too loose; do not reinstate it.
