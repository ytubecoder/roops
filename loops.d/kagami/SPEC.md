# kagami — intake spec

1. Purpose & stop condition
Keep the published roops UI mockup (`ytubecoder.github.io/roops/ui.html` — it REPLACED
the hand-crafted concept page, 2026-08-03) byte-faithful to what the REAL
`dashboard/generate.py` renders from a SHAPE-MIRROR of the live fleet — so the public
page always shows the current interface AND the current fleet silhouette (row count,
statuses, staleness, failure states), with every string and value synthesized. Per-firing "done": the check matrix is computed and drift is either
absent (green) or proposed as an open PR (amber). Cross-run "done": the
`mock-garden:drift` finding resolves (`resolved_at`) on the first firing after the PR
is merged and the live page matches again.

2. Agentic pattern
Outer shape Human-in-the-loop, per the honest v1 mapping — the approval arrow here is
the PR MERGE, not a disposition verb. Inside a firing there is deliberately no agentic
pattern at all: the original ask ("deploy an agent to fix") collapsed into
deterministic regeneration once the artifact became generator output — the fix IS
`generate.py` re-run on the pinned fixture. The engine is a single-shot interpreter of
precheck's matrix. No iterate-until-success anywhere; the cross-firing loop closes by
later firings observing the merge.

3. Type & data flow (precheck gathers vs engine interprets)
`type=agent`. precheck.sh (all deterministic): mirror the live fleet's shape into a
throwaway root via `fixture/build_root.py --source $LOOPS_ROOT` (shape crosses —
counts, statuses, types, schedules, bucketed ages, finding severities, panel types;
strings and values NEVER cross — names map to a generic pool, text is templated,
numbers are md5-seeded) → run `dashboard/generate.py --root <mirror> --now <pinned>`
→ rewrite the fixture filesystem path to a mock path → run the publish gates
(self-contained scan, real-name/path leak grep, token drift, and parity: render the
real garden locally and require every feature token it exhibits — CSS classes + tag
names, minus transient running/overdue/grey — to also render on the mirror, so the public
mockup can never silently stop showcasing the current interface; only token NAMES
surface, the real render stays in `$OUT_DIR`) → fetch the live page
(cache-busted) and byte-compare → on drift with all gates green, shallow-clone the
Pages repo, commit to the fixed branch `roops/mock-garden-refresh`, push, open or
update the single PR → print the `key: value` matrix + the exact metrics JSON, and
persist `matrix.json` to `$OUT_DIR` for render.sh. Engine: interpret the matrix into
the contract. It recomputes nothing.

4. Cadence
`daily:21:30` — UI changes ship at human pace; an evening check turns the day's UI
work into a reviewable PR by morning. Staleness expectation 24h; calendar coalescing
after sleep is fine (one catch-up firing is all this job ever needs).

5. Scope & exclusions
In scope: exactly one artifact, the published `roops/ui.html`, generated by the real
`dashboard/generate.py` from the shape-mirror. Excluded: the other hand-crafted site
pages (`site/index.html`, `site/brandkit/` — human-owned, never agent-edited by this
loop; the old `site/ui.html` concept page stays in the repo as an unpublished archive); other loops' report pages; `pagekit/kit.css` drift
(owned by `tests/test_token_drift.py`); any notion of data parity with the real fleet
(the publish target is mock-data-only BY RULE); merging (never — merge is the human
gate).

6. Guardrails
Verbatim, from project docs:
- "MOCK DATA ONLY — the publish target is public; never put internal loop names or
  real business data on these pages" (site/workflows/publish.txt) — enforced
  mechanically by the name/path leak gate; any gate failure means NO PR, alert finding.
- "deterministic code you wrote gets full power; the model gets a sandbox" (README) —
  the only remote mutation lives in precheck; the engine is at the floor on all axes.
- "Generated pages must fetch NOTHING on load" (CLAUDE.md) — enforced by running
  `tests/html_selfcontained.py` against the artifact as a publish gate.
- The loop never merges its own PR, never pushes to main of any repo, and touches no
  repo other than `ytubecoder/ytubecoder.github.io` (single fixed branch).

7. Permission axes + justification
All four axes at the report-only floor for the ENGINE (`report_only/none/none/none` —
nothing uncommented in loop.conf). The engine gets no credential_env, no network, no
exec: it physically cannot hold the pen. The one remote mutation (branch push + PR
open/update on `ytubecoder/ytubecoder.github.io`) is performed by precheck.sh —
trusted deterministic code, the same trust rule LOOP_AUTHORING §4 applies to watchdog
probes ("a plain, unsandboxed script … never governed by this axis at all").
Credential: `~/.config/roops-kagami/pat` (fine-grained PAT scoped to that one repo,
contents + pull-requests) if present, else the machine's ambient gh auth — the same
credential the manual publish workflow already uses on this exact repo. Dangerous
combos: none tripped; the nearest (combo 4, mutating `gh` in an engine allowlist) is
avoided by keeping `gh` out of the engine's reach entirely.

8. Finding identity (what a finding IS + finding_id derivation rule)
A finding is a deviation of the published mirror from the regenerated truth, or a
failure of the machinery that maintains it. Subject is the fixed literal
`mock-garden`; condition is one of an enumerated stable set:
`mock-garden:drift` · `mock-garden:gate:<check-name>` (`regenerate`,
`self-contained`, `name-leak`, `token-drift`, `parity`) · `mock-garden:pr-failed` ·
`mock-garden:live-unreachable`. No volatile data (PR numbers, URLs, hashes, byte
counts) ever appears in an id — details carry those.

9. Tier-1 semantics (ok/warn/alert meaning)
`ok` — all checks pass and live matches regenerated; emitted with ZERO findings (the
green path). `warn` — drift detected and proposed (PR open/updated, awaiting merge),
and/or live unverifiable this run. `alert` — a publish gate failed (no PR was opened)
or the PR machinery failed. Consistent with INTERFACES §4.5 by construction: the ok
case is the only one with empty findings, so the declared status passes through; every
other case's displayed status comes from max finding severity, which matches the
declared value.

10. Tier-2 metrics + panels
All computed in precheck and copied verbatim by the engine (`metrics:` line):
`mirror.tests_failed` (number panel, warn 1 / alert 2) · `mirror.drift` (0/1, number
panel, warn 1) · `mirror.pr_open` (0/1, raw fallback only) · `mirror.artifact_bytes`
(trend panel, 60-day window — page-weight creep is the long-term signal).

11. Engine/model + budget
`engine=codex`, default model. Expected a few hundred tokens/run (pure interpretation
of a ~20-line matrix). `retry_transient` default 1. `timeout_s=900` — the budget is
for precheck's network work (clone/push on a cold cache), not the engine.

12. Page output
Yes — class `snapshot`. Rendered by `render.sh` from `$OUT_DIR/matrix.json` every
promoted run (nightly, so the passing matrix is always visible, not only on drift).
Shows: check matrix as marubatsu rows (〇 pass / × fail, serif — no emoji), drift/PR
state with the PR link, artifact byte size, and the standard provenance footer.
Stat strip: checks passed · drift · PR state · bytes.
