# Verify Report-Page Render (zero engine tokens, real data)
# Project: loops
# Frequency: as needed — after ANY change to a page-enabled loop's render.sh / render_page.py, to pagekit/kit.css, to bin/redact.py, or to bin/run-loop.sh step 6.5
# Description: Prove the render + promotion-gate path end to end against the LAST REAL RUN's artifacts, without invoking an engine and without mutating state. Distinct from verify-loop-supervised.txt, which spends real engine tokens against a scratch root to prove the precheck→engine→contract path. Use this one when only the RENDER path changed. First used for the report-pages follow-up wave (SESSION_LOG 2026-07-30).

## Prerequisites
- The loop has already promoted at least one run (a `reports/<name>/latest.html` exists)
- Key fact this rides on: `render.sh` reads everything from its environment, so the runner's step-6.5
  env contract can be reproduced by hand — nothing else in the runner has to execute
- Nothing here writes to `reports/`, `state/`, or launchd; the page is rendered to a scratch path

## Steps

1. Establish a green baseline BEFORE touching anything
   - Run: cd ~/projects/loops && bash tests/run-tests.sh 2>&1 | grep -E "^Ran |^OK$|^FAILED|passed:|passed="
   - Expected outcome: zero failures, and a recorded python/shell count
   - Note the count from THIS run, not from CLAUDE.md/README — several agents commit here and the
     recorded number goes stale within hours

2. Snapshot the currently promoted page for comparison
   - Run: LOOP=<name>; cp reports/$LOOP/latest.html <scratchpad>/before.html && wc -c <scratchpad>/before.html
   - Expected outcome: a byte count you can diff against later

3. Locate the newest run's artifacts (the render's real inputs)
   - Run: RUN=$(ls -t state/runs | head -1); echo "$RUN"; ls state/runs/$RUN
   - Expected outcome: the run dir holds the loop's own input (e.g. `scan.json`) plus `page.html`
   - If the newest run belongs to a different loop, filter: `ls -t state/runs | grep <name> | head -1`

4. Render using the runner's exact step-6.5 env contract
   - Run:
     ROOT=$(pwd); cd loops.d/$LOOP && \
       LOOP_NAME=$LOOP RUN_ID="$RUN" LOOPS_ROOT="$ROOT" OUT_DIR="$ROOT/state/runs/$RUN" \
       LATEST_JSON="$ROOT/reports/$LOOP/latest.json" LOOP_DATA_DIR="$ROOT/state/loop-data/$LOOP" \
       PAGEKIT="$ROOT/pagekit" PAGE_OUT="<scratchpad>/after.html" bash ./render.sh; cd "$ROOT"
   - Expected outcome: exit 0 and a "wrote ... (N bytes, M findings)" line with the expected M
   - If fails: the message is the diagnosis — the renderer is built to fail loudly on a missing
     required file (bin/redact.py, pagekit/kit.css) rather than emit a degraded page

5. Run the promotion gate the runner would run
   - Run: python3 bin/page_envelope.py check --file <scratchpad>/after.html --expect-run-id "$RUN" --expect-loop $LOOP && echo GATE PASSED
   - Expected outcome: GATE PASSED
   - If fails on redaction: the page contains something `bin/redact.py` would redact. Do NOT invent
     a smuggling workaround — either the prose needs neutralizing at the source or the finding text
     genuinely carries a secret

6. Prove the change is output-neutral (or that the diff is exactly what you intended)
   - Run:
     diff <(sed -E 's/[0-9]{4}-[0-9]{2}-[0-9]{2}[ T][0-9]{2}:[0-9]{2}(:[0-9]{2}Z?)?//g' <scratchpad>/before.html) \
          <(sed -E 's/[0-9]{4}-[0-9]{2}-[0-9]{2}[ T][0-9]{2}:[0-9]{2}(:[0-9]{2}Z?)?//g' <scratchpad>/after.html)
   - Expected outcome: empty for a refactor. The sed strips render/generated timestamps, which
     always differ and would otherwise drown the real diff
   - If output differs and you did not intend it: stop — a "pure refactor" that moves bytes is not one

7. Confirm the page still fetches nothing on load
   - Run: python3 -c "import sys; sys.path.insert(0,'tests'); from html_selfcontained import external_subresources as e; print(e(open('<scratchpad>/after.html').read()) or 'CLEAN')"
   - Expected outcome: CLEAN. A non-empty list names the offending (tag, attribute, url)
   - Navigation `<a href>` and `data:` URIs are intentionally allowed; only fetched-on-load
     references count

8. Regenerate the dashboard and re-check the served surfaces
   - Run: python3 dashboard/generate.py --root . && for u in / /reports.html /reports/$LOOP/latest.html; do echo "$(curl -s -o /dev/null -w '%{http_code}' --max-time 10 https://loops.example.ts.net$u)  $u"; done
   - Expected outcome: three 200s. Always verify over **https** — `ts.net` is HSTS-preloaded, so a
     200 on `http://` from curl proves nothing a browser could use
   - `dashboard/*.html` is a gitignored local artifact; regenerating it is safe and never published

9. Re-run the full suite and reconcile the count
   - Run: bash tests/run-tests.sh 2>&1 | grep -E "^Ran |^OK$|^FAILED|passed:|passed="
   - Expected outcome: zero failures; the delta vs step 1 equals the tests you actually added
   - Update the counts in CLAUDE.md and README.md as part of the same commit
